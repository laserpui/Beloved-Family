# Mailing Labels

เว็บจัดการที่อยู่ผู้รับสำหรับสร้างภาพจ่าหน้าซอง โดยเก็บข้อมูลหลักใน Google Sheet
`Letter` แท็บ `ชีต1` และเก็บสำเนาในเบราว์เซอร์เพื่อใช้งานเมื่อขาดการเชื่อมต่อ

## เผยแพร่ผ่าน GitHub Pages

1. ใช้ Google Apps Script Web App deployment ที่กำหนดใน `index.html` หาก deployment เปลี่ยน ให้แก้ค่า `sheetUrl` ในโค้ดแล้วเผยแพร่หน้าเว็บใหม่
2. ใน GitHub repository ให้วาง `index.html`, `thai-addresses.js` และ `THAI_GEO_LICENSE.txt` ไว้ที่ระดับบนสุดของโฟลเดอร์ที่จะเผยแพร่ ไฟล์ `Code.gs` ทำงานใน Apps Script จึงไม่ต้องอัปโหลดเป็นส่วนของเว็บบน GitHub Pages
3. ที่ GitHub repository ไปที่ **Settings → Pages → Build and deployment** เลือก **Deploy from a branch** แล้วเลือก branch ที่อัปโหลดไฟล์และโฟลเดอร์ `/(root)` หากวางไฟล์ไว้ใน root
4. เปิด URL GitHub Pages ผ่าน HTTPS ตรวจว่าตัวเลือกจังหวัด/อำเภอ/ตำบลโหลดได้ จากนั้นเปิด **ตั้งค่า → ทดสอบการเชื่อมต่อ**
5. ก่อนใช้ข้อมูลจริง ทดลองเพิ่ม แก้ไข และลบรายการทดสอบหนึ่งรายการ ตรวจผลใน Sheet จริง รีเฟรชหน้าเว็บ และให้คิวรอซิงค์เป็นศูนย์ แล้วทดสอบดาวน์โหลด PNG/SVG จากหน้าที่เผยแพร่

GitHub Pages ให้บริการเฉพาะหน้าเว็บแบบ static; การอ่านและบันทึกผู้รับยังต้องใช้ Apps Script Web App และ Google Sheet URL ที่ฝังในโค้ดตอบการทดสอบเชื่อมต่อสำเร็จเมื่อวันที่ 10 พฤศจิกายน 2026

โปรแกรมใช้แท็บ `ชีต1` โดยตรง แท็บ `Addresses` ในไฟล์เดียวกันไม่ได้ใช้และไม่ได้ถูกลบหรือรวมข้อมูลอัตโนมัติ

## การทำงาน

- หน้า Letter แบ่งเป็น 2 หน้าในเว็บเดียวกัน: หน้า 1 แสดงรายชื่อผู้รับ พร้อมค้นหา เรียง และสร้างภาพจ่าหน้าซอง; หน้า 2 ใช้เพิ่มหรือแก้ไขข้อมูลผู้รับ กด **เพิ่มผู้รับ** เพื่อเปิดฟอร์มใหม่ หรือกดปุ่มแก้ไขของรายการเพื่อเปิดฟอร์มพร้อมข้อมูลเดิม หลังบันทึกจะกลับไปหน้ารายชื่อ
- เว็บถามรหัส `Admin1234` ก่อนเปิดหน้าแก้ไขหรือลบผู้รับแต่ละรายการ และก่อนเปิดหน้าตั้งค่าฐานข้อมูล รหัสนี้ตรวจในเบราว์เซอร์ จึงเป็นเพียงการป้องกันการกดใช้งานโดยไม่ตั้งใจ ไม่ใช่สิทธิ์เข้าถึง Google Sheet หรือ Apps Script API
- หาก Web App ของ Apps Script ถูกเผยแพร่แบบให้ทุกคนเข้าถึงได้ ผู้ที่ทราบ URL จะสามารถอ่านและเปลี่ยนข้อมูลผู้รับได้ ควรกำหนดการเข้าถึง URL และสิทธิ์ deployment ให้ตรงกับผู้ใช้งานจริง
- โหมดออฟไลน์แก้ไขสำเนาในเบราว์เซอร์และนำการเปลี่ยนแปลงเข้าคิวเพื่อซิงค์เมื่อเชื่อมต่ออีกครั้ง
- การเพิ่มหรือแก้ไขผู้รับจะแสดงหน้าต่างยืนยันพร้อมชื่อก่อนบันทึก การลบจะแสดงชื่อผู้รับก่อนยืนยัน หากกดยกเลิก ข้อมูลและคิวซิงค์จะไม่เปลี่ยน
- ข้อมูลที่เก็บใน `localStorage` แยกตามที่อยู่เว็บ เมื่อย้ายจากไฟล์ในเครื่องไป GitHub Pages ให้ซิงค์คิวเดิมให้หมดก่อน รายชื่อที่บันทึกใน Google Sheet จะโหลดกลับมาเมื่อเชื่อมต่อสำเร็จ
- ช่องข้อความท้ายผู้รับอยู่ในหน้าตัวอย่างภาพ กรอกก่อนดาวน์โหลดได้เฉพาะเคสนั้น เมื่อเปิดหน้าตัวอย่างครั้งใหม่ช่องจะว่าง และข้อความนี้ไม่ถูกบันทึกในรายชื่อหรือ Google Sheet หาก Sheet มีคอลัมน์ `subject` จากเวอร์ชันก่อน โปรแกรมจะคงข้อมูลเดิมไว้โดยไม่แสดงหรือแก้ไขคอลัมน์นั้น
- รายการที่ยังซิงค์ไม่สำเร็จอยู่ในคิวของเบราว์เซอร์นั้น อย่าล้างข้อมูลเว็บไซต์ก่อนคิวเป็นศูนย์ หากเปลี่ยน URL ในโค้ดหลังใช้งานออฟไลน์ รายการในคิวจะถูกส่งไปยังฐานข้อมูลใหม่เมื่อเปิดเว็บอีกครั้ง
- ตัวอย่างจ่าหน้าจะตัดบรรทัดและลดขนาดอักษรให้พอดีกับพื้นที่ของซองที่เลือก หากข้อความยาวเกินพื้นที่ ระบบจะเตือนและปิดปุ่มดาวน์โหลดจนกว่าจะย่อข้อความ
- ภาพส่งออกใช้ความละเอียด 3 เท่าของตัวอย่างบนจอ ไฟล์ PNG เหมาะสำหรับใช้งานภาพทั่วไป ส่วน SVG ระบุขนาดซองเป็นเซนติเมตร ให้พิมพ์ที่มาตราส่วน 100% และตรวจขนาดจริงกับเครื่องพิมพ์
- รายชื่อจังหวัด อำเภอ และตำบลอยู่ใน `thai-addresses.js` ซึ่งสร้างจากชุดข้อมูล v2 ของ [Thai Province Data](https://github.com/kongvut/thai-province-data) และใช้ตาม [MIT License](THAI_GEO_LICENSE.txt) ที่แนบไว้

## ตรวจโค้ดในเครื่อง

`node verify-local.js` ทดสอบ Apps Script ว่าข้อความเฉพาะภาพไม่ถูกบันทึก ด้วยตัวจำลองโดยไม่แก้ไข Google Sheet จริง

`node verify-layout.js` ทดสอบการจัดข้อความของซองทั้ง 5 ขนาดด้วย Canvas จำลอง

`node verify-confirmations.js` ทดสอบการยืนยันและยกเลิกเพิ่ม แก้ไข ลบ โดยไม่เชื่อมต่อ Sheet จริง
